# 입출고 ERP (원료육 · 완제품 · 야채 · 부자재 · 소스)

냉동고·냉장고 재고와 입출고 이력을 **여러 사람이 함께** 쓰는 웹앱입니다.
Supabase 로그인으로 들어가고, 데이터는 Supabase에 저장되므로 PC·폰 어디서 열어도 같은 내용이 보입니다.

- 모드: `📥 입고` · `🧊→❄️ 해동` · `❄️→🧊 재냉동` · `📤 출고(현장/업체/택배/기타)`
- 대분류: **원료육 · 완제품(자체생산) · 완제품(매입) · 야채/농산물 · 부자재 · 소스/양념 · 기타** (직접 입력도 가능)
- 표: 냉동고 재고 · 냉장고 재고 · 입출고 내역 — **머리글을 눌러 정렬**하고 **칸별 값 필터**를 씁니다.
- **열 너비**: 머리글 오른쪽 경계를 **드래그**해 엑셀처럼 늘리고 줄입니다. 경계를 **더블클릭**하면 내용에 맞춰집니다.
  바꾼 너비는 브라우저(localStorage)에 저장돼 새로고침해도 그대로이고, `↔ 열 너비 초기화`로 되돌립니다.
- **기간 선택**: `📅 기간선택`(또는 기간 표시줄·날짜칸 클릭) → 이카운트와 같은 **2개월 달력 팝업**.
  좌·우 달력은 각자 연도·월을 바꿀 수 있어 **1년 넘는 기간도** 그대로 클릭해 고를 수 있습니다.
  빠른 버튼 3줄(오늘·전일·주간·전주·당월·전월·올해 / 상반기·하반기·1~4분기·오늘까지 / 1~12월) + `적용`·`취소`.
- **검색**: `🔍 검색` 버튼 또는 검색창에서 Enter — 검색어와 기간을 한 번에 확정해 조회합니다.
- **단가**: 입고는 **입고단가(원/kg)**, 출고는 **출고단가(원/kg)**만 씁니다. 회계·정산·세금계산서 항목은 넣지 않았습니다.
  입출고 내역 표에는 `입고단가(원/kg)`·`출고단가(원/kg)` 두 칸이 나란히 있고,
  입고 줄은 **입고단가 칸에만** 금액이, 출고 줄은 **출고단가 칸에만** 금액이 들어갑니다(해동·재냉동은 둘 다 `-`).
- 금액: 단가(원/kg)·재고금액(원)/금액(원)을 표에 표시하고, 상단에 **총 재고금액**을 보여줍니다.
- 입력 수정: 화면에서 넣은 입출고는 `수정`으로 고칠 수 있고, 로트 정보(대분류·품목명·브랜드·기준단가 등)도 고칠 수 있습니다.
- **브랜드**: 재고표와 입출고 내역 표 모두 `브랜드` 열을 보여줍니다. 이력의 브랜드는 그 이력이 가리키는 로트의 브랜드이며,
  로트 `수정`에서 브랜드를 바꾸면 그 로트의 이력에도 함께 바뀝니다(브랜드가 없으면 `-`).

## 설치 1단계 — Supabase에 표·초기 데이터 넣기

**처음 설치하는 경우** — `downloads/supabase_setup.sql` (또는 같은 내용의 `.txt`)을 실행합니다.

1. <https://supabase.com/dashboard> → 프로젝트(`gzufnyglmvgzqltepock`) 선택
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. `supabase_setup.sql` 내용 **전체**를 복사해 붙여넣고 **Run**
4. 맨 아래 결과가 아래처럼 나오면 성공

| 로트수 | 냉동총재고kg | 냉장총재고kg | 재고금액원 | 입출고이력수 | 미정산건수 |
|---|---|---|---|---|---|
| 177 | 7216.37 | 3598.40 | 0 | 607 | 0 |

*(표의 `미정산건수`는 SQL 스크립트가 같이 알려주는 값입니다. 화면에서는 쓰지 않습니다.)*

**이미 쓰고 있는 DB를 그대로 업그레이드하는 경우** — `downloads/supabase_migrate_v3.sql` (또는 `.txt`)을 실행합니다.
기존 데이터를 지우지 않고 아래를 더합니다. **v1으로 쓰던 DB에도, v2로 쓰던 DB에도 그대로 실행됩니다.**

1. (v2가 아직 안 된 DB라면) `lots`에 `major_category`(대분류)·`unit_price`(기준단가), `tx_logs`에 `major_category`·`unit_price`·`total_amount`(금액) 열 추가
2. 축종 표기 `돈 → 돈육`, `우 → 우육`, `계 → 계육`, `양 → 양육` 로 바꾸기 + 대분류를 `원료육` 으로 채우기
3. 저장 함수(`tx_apply`) 교체 + `tx_update`(입력 수정) · `lot_update`(로트 수정) 함수 추가
4. 권한(RLS)·실시간 등록 다시 맞추기

> 예전(v3) 화면에서 쓰던 `trade_type`(거래구분)·`settle_status`(정산상태)·`tax_invoice_status`(세금계산서) 열은
> DB에 그대로 남아 있고 이 스크립트도 함께 만듭니다. **지금 화면은 이 값을 보내지도, 읽지도 않습니다** —
> 그래서 이미 v3 스크립트를 실행해 둔 DB라면 SQL을 다시 실행하지 않고 화면만 바꿔도 그대로 동작합니다.

> 실행 전에 Supabase → Database → Backups 에서 백업을 한 번 받아 두세요.
> 두 스크립트 모두 여러 번 실행해도 안전합니다(초기 데이터는 표가 비어 있을 때만 들어갑니다).
> `supabase_migrate_v2.sql` 은 지난 단계(v2)용입니다. 지금은 **v3** 하나만 실행하면 됩니다.

## 설치 2단계 — 계정 만들기

이 프로젝트는 **이메일 확인(Confirm email)이 켜져 있어** 앱에서 만든 계정은 메일 확인을 눌러야 로그인됩니다.
회사 내부용으로 바로 쓰시려면 둘 중 하나를 고르세요.

- **A. 이메일 확인 끄기 (권장)**
  Supabase → **Authentication** → **Sign In / Providers** → **Email** → `Confirm email` 끄고 저장.
- **B. 관리자가 계정을 직접 추가**
  Supabase → **Authentication** → **Users** → **Add user** → 이메일·비밀번호 입력, `Auto Confirm User` 체크.

작업자 이름은 계정을 만들 때 넣은 이름(`User Metadata → name`)으로 이력에 표시되고,
없으면 이메일 앞부분이 표시됩니다.

## 쓰는 법

| 하고 싶은 일 | 방법 |
|---|---|
| 입고 | `📥 입고` → 대분류·소분류·제품명·입고일·소비기한·중량·단가 입력 → 저장 |
| 해동 | 냉동고 재고표에서 로트 줄의 `해동` → 중량 입력 → 저장 |
| 재냉동(생산 취소) | 냉장고 재고표에서 `재냉동` → 중량·사유 입력 → 저장 |
| 출고 | 재고표에서 `출고` → 출고처 구분(현장/업체/택배/기타) → 상세·단가 입력 → 저장 |
| 잘못 입력 수정 | `📋 입출고 내역`에서 그 줄의 `수정` → 값 고치고 저장 (재고가 한 번에 다시 계산됩니다) |
| 로트 정보 수정 | 재고표 줄의 `수정` → 대분류·소분류·품목명·브랜드·원산지·기준단가·날짜 |
| 잘못 입력 취소 | `📋 입출고 내역`에서 `취소` → 재고가 입력 전으로 되돌아갑니다 |
| 정렬 | 표의 머리글을 누를 때마다 `오름차순 → 내림차순 → 해제` |
| 값 필터 | 머리글 오른쪽 `▾` → 값 체크박스(검색·전체·모두 해제·필터 해제) |
| 기간으로 보기 | 표 위 `전체 / 오늘 / 이번주 / 이번달 / 유통임박` 또는 `📅 기간선택`(2개월 달력) · 시작일~종료일 |
| 열 너비 바꾸기 | 머리글 오른쪽 경계를 드래그 / 더블클릭=내용에 맞춤 / `↔ 열 너비 초기화` |
| 검색 확정 | 검색어 입력 후 `🔍 검색` 또는 Enter |
| 대분류로 보기 | 툴바 `대분류` 선택(원료육/완제품(자체생산)/완제품(매입)/야채/농산물/부자재/소스/양념/기타) |
| 입고·출고 단가 보기 | `📋 입출고 내역` 표의 `입고단가(원/kg)`·`출고단가(원/kg)` 두 칸 (해당 없는 칸은 `-`) |
| 엑셀로 받기 | 오른쪽 위 `⬇ 냉동고 재고` / `⬇ 냉장고 재고` / `⬇ 입출고 내역` |

- **단가와 금액은 서로 맞물립니다**: 중량·단가를 넣으면 금액이 계산되고, 금액을 고치면 단가가 역산됩니다.
  기존 로트를 해동·재냉동·출고하면 그 로트의 기준단가가 자동으로 채워집니다(바꿀 수 있음).
- **입고단가와 출고단가는 따로**입니다. 재고(`lots.unit_price`)는 **입고단가**를 가지고 재고금액을 계산하고,
  출고할 때 넣은 **출고단가**는 그 이력(`tx_logs.unit_price`)에만 남습니다. 현장·내부출고는 0원으로 두거나 원가를 그대로 쓸 수 있습니다.
- 입출고 내역 표·CSV는 단가를 **`입고단가(원/kg)`·`출고단가(원/kg)` 두 열**로 나눠 보여줍니다.
  입고 줄은 입고단가 칸에만, 출고 줄은 출고단가 칸에만 금액이 들어가고, 해동·재냉동은 둘 다 `-`입니다.
- **입고 단가 비교**: 입고 화면에서 품목명과 단가를 넣으면 단가칸 아래에
  직전 입고가 대비 변동(▲/▼, 금액·%), 과거 입고 최저·평균·최고가가 뜹니다.
  직전가(또는 평균가)와 30% 이상 차이 나면 **단가 급변 경고**가 나와 오타(0 하나 더 입력 등)를 잡습니다.
  *지금까지 쌓인 이력에는 단가가 없어(0) 처음에는 "첫 단가 입력"으로 표시됩니다. 단가를 넣기 시작하면 비교가 됩니다.*
- 같은 대분류·제품명·업체명·입고일·소비기한이면 한 로트로 합쳐지고, 다르면 새 로트가 됩니다.
- 소비기한이 짧은 것부터(선입선출) 위에 옵니다.
- **실시간 공유**: 한 사람이 입력하면 다른 기기 화면이 1~2초 안에 갱신됩니다(연결이 막히면 1분마다 자동 새로고침).
- 저장·수정·취소는 서버 함수가 **한 번에(트랜잭션)** 처리합니다. 두 사람이 동시에 눌러도 재고가 어긋나지 않습니다.
- 처음 엑셀에서 옮긴 이력 607건은 `수정`·`취소`할 수 없습니다(원본 기록 보존). 화면에서 입력한 건만 고치거나 되돌릴 수 있습니다.
- 표가 화면보다 넓으면 **표 안에서 좌우로 밀어** 보거나, 머리글 경계를 드래그해 열을 좁힙니다.
  오른쪽 `작업`(해동/출고/수정/취소) 열은 항상 붙어 있습니다. `↔ 열 너비 초기화`로 처음 너비로 돌아갑니다.

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| "DB 표·함수를 찾을 수 없습니다" | `supabase_setup.sql`(새 설치) 또는 `supabase_migrate_v3.sql`(기존 DB)을 아직 실행하지 않음 |
| "이메일 또는 비밀번호가 맞지 않습니다" | 오타, 또는 아직 이메일 확인 전 → 2단계 참고 |
| "이메일 확인이 아직 안 됐습니다" | 받은 메일의 확인 링크를 누르거나, `Confirm email`을 끄고 계정을 다시 만들기 |
| 실시간 표시가 "자동 새로고침(1분)" | 그 환경에서 웹소켓이 막힌 경우. 기능은 그대로이고 1분마다 갱신됩니다 |
| 표가 옆으로 잘림 | 표 안에서 좌우로 밀거나, 머리글 오른쪽 경계를 드래그해 열 너비를 줄입니다(더블클릭=내용에 맞춤, `↔ 열 너비 초기화`=처음대로) |
| "DB 함수를 찾을 수 없습니다" | 예전 SQL을 실행한 DB입니다. `supabase_migrate_v3.sql`을 한 번 실행하면 새 함수·열이 들어갑니다 |
| 단가·금액이 `-` 로 보임 | 그 로트에 단가를 아직 넣지 않은 상태. 로트 `수정`에서 기준단가를 넣으면 채워집니다 |

## 개발자용

- Supabase 주소·anon 키: `app.js` 맨 위 `CONFIG`.
- 데이터 흐름: `POST /rest/v1/rpc/tx_apply` (입고/해동/재냉동/출고) ·
  `tx_update` (입력 수정) · `lot_update` (로트 수정) · `tx_undo` (취소) ·
  `GET /rest/v1/lots`·`tx_logs` (조회) · Realtime 웹소켓(없으면 1분 폴링).
- 외부 라이브러리·CDN을 쓰지 않습니다(fetch + WebSocket 직접 사용). `index.html` 하나로 어디서든 동작.
- 열 너비는 `localStorage['meatERP.colw.v3']` 에 `{lot:{컬럼키:px}, log:{...}}` 로 저장됩니다.
- 테스트(작업 환경 기준)
  - `python3 work/erp-web/test/test_core.py` — 문법(esprima) + 계산·정렬·필터·단가비교·기간(2개월 달력)·입고/출고단가 분리·CSV/엑셀 단위 검증
