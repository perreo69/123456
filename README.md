# 원료육 입출고 ERP (Supabase 연동 웹앱)

냉동고·냉장고 원료육 재고와 입출고 이력을 **여러 사람이 함께** 쓰는 웹앱입니다.
Supabase 로그인으로 들어가고, 데이터는 Supabase에 저장되므로 PC·폰 어디서 열어도 같은 내용이 보입니다.

- 화면 구성은 **2번 문서 기준**(`날짜 | 구분 | 창고 | 제품명 | 업체명 | 입고일 | 소비기한 | 중량(kg) | 출고처 · 비고`)이고, 여기에 **작업자** 열을 더했습니다.
- 모드: `📥 입고` · `🧊→❄️ 해동` · `❄️→🧊 재냉동` · `📤 출고(현장/업체/택배/기타)`
- CSV 내려받기 3종: **냉동고 재고**, **냉장고 재고**, **입출고 내역**

## 폴더

```
index.html   화면
style.css    스타일
app.js       로직 (Supabase 주소·키가 맨 위 CONFIG에 있음)
```
빌드 과정이 없는 정적 사이트입니다. 이 폴더를 그대로 올리면 됩니다.

## 설치 1단계 — Supabase에 표·초기 데이터 넣기 (한 번만)

1. <https://supabase.com/dashboard> → 프로젝트(`gzufnyglmvgzqltepock`) 선택
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. `downloads/supabase_setup.sql` 내용 **전체**를 복사해 붙여넣고 **Run**
4. 맨 아래 결과가 아래처럼 나오면 성공

| 로트수 | 냉동총재고kg | 냉장총재고kg | 입출고이력수 |
|---|---|---|---|
| 177 | 7216.37 | 3598.40 | 607 |

> 이 스크립트가 만드는 것: `lots`·`tx_logs` 표, 저장·취소 함수(`tx_apply`/`tx_undo`),
> 로그인한 사람만 읽고 쓰는 RLS 정책(비로그인 `anon` 완전 차단), 실시간 발행 등록,
> 그리고 2026-11-16 기준 재고(로트 177개)와 이력 607건.
> 다시 실행해도 기존 데이터는 지우지 않습니다(초기 데이터는 표가 비어 있을 때만 들어갑니다).

## 설치 2단계 — 계정 만들기

이 프로젝트는 **이메일 확인(Confirm email)이 켜져 있어** 앱에서 만든 계정은 메일 확인을 눌러야 로그인됩니다.
회사 내부용으로 바로 쓰시려면 둘 중 하나를 고르세요.

- **A. 이메일 확인 끄기 (권장)**
  Supabase → **Authentication** → **Sign In / Providers** → **Email** → `Confirm email` 끄고 저장.
  이후 앱의 **계정 만들기** 탭에서 만든 계정은 바로 로그인됩니다.
- **B. 관리자가 계정을 직접 추가**
  Supabase → **Authentication** → **Users** → **Add user** → 이메일·비밀번호 입력, `Auto Confirm User` 체크.
  직원분들 계정을 이렇게 만들어 주고 이메일·비밀번호만 알려주면 됩니다(가입 기능은 그대로 둬도 무방).

작업자 이름은 계정을 만들 때 넣은 이름(`User Metadata → name`)으로 이력에 표시되고,
없으면 이메일 앞부분이 표시됩니다.

## 설치 3단계 — 웹에 올리기

**GitHub Pages (무료, 간단)**

1. GitHub에 저장소를 하나 만듭니다(Public).
2. 이 폴더의 `index.html` · `style.css` · `app.js` 세 파일을 저장소 최상위에 올립니다.
3. 저장소 **Settings → Pages** → Branch: `main` / `(root)` → Save.
4. 1~2분 뒤 `https://<아이디>.github.io/<저장소>/` 주소로 열립니다.

> 화면 코드는 공개되지만 **재고·이력 데이터는 로그인해야만** 보입니다(anon 키로는 표에 접근 불가).
> anon 키는 원래 공개용 키입니다.

**Vercel (비공개 저장소도 가능)**

1. <https://vercel.com> → GitHub으로 로그인 → **Add New → Project** → 저장소 선택
2. Framework Preset: **Other**, Build Command 없음, Output Directory: `.` → Deploy

**폰에서 앱처럼 쓰기**
올린 주소를 폰 브라우저(크롬)로 열고 → 메뉴 → **홈 화면에 추가**. 아이콘을 누르면 바로 열립니다.

## 쓰는 법

| 하고 싶은 일 | 방법 |
|---|---|
| 입고 | `📥 입고` → 받는 창고(냉동/냉장) → 제품명·입고일·소비기한·중량 입력 → 저장 |
| 해동 | 냉동고 재고표에서 로트 줄의 `해동` 버튼 → 중량 입력 → 저장 |
| 재냉동(생산 취소) | 냉장고 재고표에서 `재냉동` 버튼 → 중량·사유 입력 → 저장 |
| 출고 | 재고표에서 `출고` 버튼 → 출고처 구분(현장/업체/택배/기타) → 상세 입력 → 저장 |
| 잘못 입력 취소 | `📋 입출고 내역`에서 그 줄의 `취소` → 재고가 입력 전으로 되돌아갑니다 |
| 엑셀로 받기 | 오른쪽 위 `⬇ 냉동고 재고` / `⬇ 냉장고 재고` / `⬇ 입출고 내역` (엑셀에서 바로 열립니다) |

- 같은 제품이라도 **입고일·소비기한이 다르면 다른 로트**로 표시되고, 소비기한이 짧은 것부터(선입선출) 위에 옵니다.
- **실시간 공유**: 한 사람이 입력하면 다른 기기 화면이 1~2초 안에 갱신됩니다(연결이 막히면 1분마다 자동 새로고침).
- 저장·취소는 서버 함수가 **한 번에(트랜잭션)** 처리합니다. 두 사람이 동시에 눌러도 재고가 어긋나지 않습니다.
- 처음 엑셀에서 옮긴 이력 607건은 `취소`할 수 없습니다(원본 기록 보존). 화면에서 입력한 건만 취소됩니다.

## 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| "DB 표를 찾을 수 없습니다" | `supabase_setup.sql`을 아직 실행하지 않음 → 1단계 실행 |
| "이메일 또는 비밀번호가 맞지 않습니다" | 오타, 또는 아직 이메일 확인 전 → 2단계 참고 |
| "이메일 확인이 아직 안 됐습니다" | 받은 메일의 확인 링크를 누르거나, `Confirm email`을 끄고 계정을 다시 만들기 |
| 실시간 표시가 "자동 새로고침(1분)" | 그 환경에서 웹소켓이 막힌 경우. 기능은 그대로이고 1분마다 갱신됩니다 |
| 표가 옆으로 잘림 | 화면이 좁을 때는 표 안에서 좌우로 밀어 볼 수 있습니다 |

## 개발자용

- Supabase 주소·anon 키: `app.js` 맨 위 `CONFIG`.
- 데이터 흐름: `POST /rest/v1/rpc/tx_apply` (입고/해동/재냉동/출고) · `POST /rest/v1/rpc/tx_undo` (취소) ·
  `GET /rest/v1/lots`·`tx_logs` (조회) · Realtime 웹소켓(없으면 1분 폴링).
- 외부 라이브러리·CDN을 쓰지 않습니다(fetch + WebSocket 직접 사용). `index.html` 하나로 어디서든 동작.
- 테스트(작업 환경 기준)
  - `python3 work/erp-web/test/test_core.py` — 문법(esprima) + 계산/CSV 단위 검증
  - `python3 work/erp-web/test/test_ui.py --shot` — 실제 Chromium으로 로그인·저장·취소·CSV·모바일 화면 검증(가짜 백엔드)
    (작업 환경에는 `tool-results/chromelibs`에 받아 둔 라이브러리로 Chromium을 띄웁니다.)
  - `node work/erp-web/test/test_sql.mjs` — `supabase_setup.sql`을 실제 PostgreSQL(PGlite)에 실행해 표·함수·RLS·초기 합계 검증
    (Node와 `@electric-sql/pglite`가 필요합니다. 이 작업 환경에서는 `tool-results/node`, `tool-results/pgtest`에 받아 두었고, 7일 뒤 자동 정리되므로 그 뒤에는 다시 받아야 합니다.)
- `downloads/supabase_setup.sql`은 `python3 work/erp-web/tools/build_setup_sql.py`로 `work/erp/data.json`에서 다시 만들 수 있습니다.
